## Approved implementation limits

The following owner decisions apply to every deliverable.

`runtime_logging.py` remains the sole editable logging backend and `journal.py` remains a small adapter. Canonical Logging v1 does not introduce per-call UUIDs, parent-call relationships, call trees, generalized tracing, monitoring or workflow modelling.

Bare `journal.checkpoint()` is primarily a targeted inside-the-call diagnostic tool. Do not add routine bare checkpoints merely to duplicate normal call completion or existing events. Counted checkpoints are appropriate where the executing code owns truthful completed-work state.

For `collect_records`, the approved progress measure is **completed inputs / total inputs**. Use a trivial local completed-input counter or `enumerate(logs, 1)`, emitting only after each input has completed, against the already available `len(logs)`. Do not substitute distinct accumulated evidence hashes, rescan inputs or recompute application work for logging.

Do not add logging edits to parser, matcher, decoder, rules, clustering, ingestion, database-handler internals, Watcher lifecycle or `harvester` merely to broaden coverage. Their approved no-change dispositions remain in force.

Task 10 is an interface dependency only: Canonical Logging may consume a resolved writable destination and validated settings supplied by application configuration, while retained learner execution remains configuration-independent. Task 09 does not redesign Task 10.

Each delivery preserves only the exact current bytes it will edit, including prior absence for new files and directly coupled atomic edits, as its rollback baseline. Wider reproduction/authentication inputs remain separate. Retained releases are never modified in place.

Existing component exception/error ownership remains unchanged unless the new canonical logging code itself causes a concrete duplicate or masking problem. The bounded Learner receipt/terminal repair identified in the approved plan is the specific exception.

Synthetic or fault-injection testing remains subject to explicit owner approval for each individual test.
